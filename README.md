# KISS 官方情报（kiss_info_plugin）

> 作者：紫小贱　｜　版本：1.0.1　｜　适用核心：>= 2.29.7

一个专门盯 KISS 官方的插件。COM3D2、CM3D2、CRC3D、CR EditSystem 的版本号、官方公告、活动、DLC 情况，全都给你抓回来，顺手把日文标题翻译好再递到嘴边。

说人话就是：以后不用你自己一遍遍刷官网了，我替你盯。

---

## 它能做什么

- **版本情报**：CM3D2 / COM3D2＆2.5 / CRC3D / CR EditSystem 的最新版本号与更新日期，一次拿全
- **官方博客**：按月份抓公告，标题直接给你，想看细节就切 full
- **活动与 DLC**：官网活动页、DLC 商店都盯着，上新不会漏
- **缓存 + 指纹比对**：命中缓存零 token 秒回；没变化就只告诉你「没变化」，不浪费你一个字
- **自动检查（可选）**：开了之后按你设的间隔自己去看一眼，有更新就按你指定的会话推过去（默认关，只在你点头之后才动）

## 装法

1. 把 `kiss_info_plugin` 整个文件夹丢进 `data/plugins/`
2. 重启 / 重载插件
3. 进插件配置页，确认「启用插件」和「启用 LLM 工具」是开的

就这样，没别的步骤。装不好别怪插件，先怪你手。

## 用法

### 1. LLM 工具（默认推荐）

注册的工具：`kiss_info_query`

| 参数 | 说明 |
| --- | --- |
| `depth` | `brief`（默认）给版本号/标题 **+ 原文链接**（方便 bot 查证与引用）；`full` 再给更多条目（12 条）与**正文摘要** |
| `force` | `true` 无视缓存重新抓，想看最新就用它 |
| `month` | `YYYYMM`（如 `202608`）查那个月的博客归档 |
| `source` | 只看某一源：`cm3d2` / `com3d2` / `crc3d` / `cres` / `news` / `dlc_shop`（也认中文名） |
| `keyword` | 按标题关键词过滤，如 `アップデート`、`DLC`、`発売` |

**链接是一直都带的**：每条动态后面直接跟原文地址（`- 2026-10-08 标题 → https://…`），
所以 bot 不管用什么深度都能引用、查证或者让你点开看；`full` 只是**再加**最新几篇的正文摘要。

也就是说：**bot 可以自己决定要不要深挖**——想只看某个游戏、翻某个月的旧公告、或者按关键词捞条目，
都可以直接传参。日文标题交给模型翻成中文再讲给你听。

### 2. 命令式

默认关着，想用就去配置里打开「启用命令」，然后自己填触发词，默认是 `/kiss`。消息以触发词开头就会响应，不限于斜杠式，你怎么顺口怎么来。

### 3. 自动推送

「自动检查更新」+「推送作用域目标」：

- `群=qq:gm:群号`
- `私聊=qq:dm:QQ号`

每行一个，留空就是不推。别把一堆群塞进去，出了事我不管。

**推送方式**（`push_mode`，默认 `bot`）：

- **`bot`（推荐）**：把情报作为一条**系统消息**注入消息管线，让 AI **用自己的口吻**播报
  （会顺手翻日文标题、突出重点）。跟你的 bot 人设是一致的语气，不是机械转发。
- **`raw`**：不经过 AI，直接把整理好的原文投递到目标会话（省 token、绝对稳定）。

**同时机械投递**（`push_also_raw`，默认关）：开着的话**两种一起发**——
先落一份整理好的原文，再让 AI 用自己的口吻播报一遍，互不替代。
适合「既想让群友一眼看到原始情报，又想看 bot 怎么点评」的场景。
（选 `raw` 时本来就发原文，这个开关不需要开，开了也不会重复发。）

`bot` 模式下如果目标适配器取不到（比如写错了 adapter 名），会自动退回 `raw` 投递，情报不会丢。

## 配置项速览

| 项 | 默认 | 备注 |
| --- | --- | --- |
| enabled | 开 | 关掉之后工具和命令都不生效 |
| enable_llm_tool | 开 | 是否把 `kiss_info_query` 给模型用 |
| enable_command | 关 | 要不要响应触发命令 |
| commands | `/kiss` | 每行一个 |
| content_depth | brief | brief / full |
| auto_check | 关 | 自动检查更新 |
| push_mode | bot | bot=让 AI 用自己的口吻播报；raw=直接投递原文 |
| push_also_raw | 关 | 开着则「bot 播报 + 机械投递原文」两种一起发 |
| check_interval | 86400 | 秒，默认一天 |
| push_targets | 空 | 推送目标，一行一个 |
| src_* | 全开 | 各数据源开关，嫌吵就单独关 |

## 注意事项（认真看，不然别来问我）

- 抓的是 KISS 官网，**你得能连上**。梯子不稳的话结果时灵时不灵，那不叫 bug，那叫网络问题
- 缓存命中是零 token 秒回，所以「怎么还是旧数据」的时候先想想是不是就该是旧的，或者直接传 `force=true`
- 官网改版会导致解析失灵，我这边是按现有页面结构写的；真被我撞上了，告诉我，我去修
- 自动检查默认关闭是故意的，别怪我没主动推

### v1.0.1（兼容与稳定性修复，用法与输出格式不变）

- 🐛 **自动推送与命令此前其实发不出去**：调用的是框架里并不存在的 `ctx.send_to` 与 `event.reply`
  （异常被 except 吞掉）——现在统一走 `ctx.send_message_chain`，两条链路实测可送达。
  这同时修好了 2.x 与 3.0（3.0 的会话接口全异步，发送入口同名同签名）。
- 🐛 **命令主人校验恒为假**：`event.user_id` 取不到值（发送者在 `event.message.sender` 上），
  现在 `/kiss 推送|开|关` 的主人才真的能用。
- ⚡ **不再卡住事件循环**：抓取与缓存读写全部移出主线程（`asyncio.to_thread`），6 个源**并发**抓取。
  原先串行 + 阻塞，最坏情况（网络差时 3 次重试 × 6 源）能把整个 bot 卡住一分多钟。
- 🧠 **缓存改为结构化数据**：命中缓存依旧是零网络零 token 秒回，但内容**保真**——
  旧实现只缓存一行拼接指纹，新闻源命中时会甩出一长串挤在一起的标题，版本源还会出现 `date=None`。
  老缓存文件自动升级（首次命中时重抓一次即可）。
- 🔁 **自动检查任务纳入生命周期**：随 `terminate` 取消、`enabled=false` 即停、命令改配置即时生效；
  抓取失败只在日志与工具输出里体现，不再每个检查周期往群里推失败信息。
- 🔗 **depth=full 真的更详细了**：full 给更多条目（12 条 vs brief 的 5 条）并附原文链接；
  解析器同时捕获链接（对老结构仍有兜底）。
- 🧹 **命令写配置写对了地方**：`/kiss 推送|开|关` 现在写入真实的插件配置
  （`data/config/plugins/kiss_info_plugin.json`），面板与框架立即可见；此前写进 `data/plugin_data/`
  下一个没人读的文件，等于没生效。
- 🗣️ **自动推送默认改为「让 bot 用自己的口吻播报」**：不再机械转发，而是把情报作为系统消息注入消息管线
  （与 hotnews 同款做法），AI 会按人设翻日文、抓重点讲给群友。想要机械投递就把 `push_mode` 设成 `raw`；
  想**两种同时要**就打开 `push_also_raw`（先落一份原文，再让 bot 播报一遍）；
  `bot` 模式下适配器取不到会自动退回 `raw`，不会丢情报。
- 🔎 **工具支持定向查询与深挖**：新增 `month`（查某月归档）、`source`（只看某一源）、`keyword`（标题关键词）；
  **条目带原文链接**（brief/full 都给，方便查证与引用），`depth=full` 再附**正文摘要**
  （每源最新 3 篇、单篇 400 字上限，控 token）。命令层原有的 `/kiss 历史 YYYYMM` 与之一致。
- 🏷️ manifest 补 `repo` 与 `tags`；schema 的 `enum` 改为 `string` + `options`（两代框架均已废弃 `enum`）。
